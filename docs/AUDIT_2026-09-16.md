## Multi-engine overlap contract

`core/signal_contract.py` defines immutable engine-level evidence. `core/signal_consensus.py` measures agreement and conflict while counting each independent evidence group once. Multiple implementations consuming the same feed therefore cannot manufacture independent confirmation simply by duplicating an indicator.

## Research integrity

The project must not convert an engineering pass into a profitability claim. Current documentation explicitly separates `ENGINEERING_VALID`, `RESEARCH_VALIDATED`, and `LIVE_ELIGIBLE`. The final state cannot be `LIVE_ELIGIBLE` without current reproducible statistical evidence.

## Verification

GitHub Actions is the authoritative execution environment for this repository because the working environment cannot use a full repository clone. The dev-to-main synchronization workflow is intentionally fail-closed: main is synchronized only after all defined checks complete successfully.

## Remaining evidence requirement

The infrastructure work does not manufacture a new profitable sample. A current research run still has to be performed on valid historical/forward data with realistic fees, spread, slippage, funding, temporal separation, regime coverage, and rejected-signal outcome attribution. Until that evidence passes the research gate, live execution remains blocked.
